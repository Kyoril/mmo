# Alestia launcher redesign

The Windows launcher now uses the approved A layout: a shared fantasy frame and top navigation, Home with a refreshed hero, two news cards and an update summary, a News browser with an internal article reader, patch history with a scrolling reader, and functional launcher settings. The update dock stays visible on every page.

The logical window is 1140 x 740. Fonts, artwork and hit testing scale together. On smaller work areas the window scales down to remain accessible. Page artwork is cached separately from changing download progress and hover feedback.

## Preview and build

Build the `launcher` target using Debug or Release. The worktree's configured solution is `build/mmo.slnx` (or the solution generated by your CMake version). The executable is `bin/<configuration>/Launcher.exe`.

Run `Launcher.exe --preview` to browse the launcher without starting updates or self-updating the executable. Play stays disabled in this mode. Normal startup checks for game updates and launcher self-updates as before.

For repeatable visual checks, run:

```powershell
./bin/Debug/Launcher.exe --render-preview build/launcher-previews
```

This exports actual software-rendered BMP screenshots at 100%, 150% and 200%, exercising navigation, article scrolling, saving the settings checkbox, disabled/enabled Play, keyboard activation, and failure/ready states. It exits with a nonzero code if an interaction check fails. It does not contact the update server or write installation files.

## Publishing news and release notes

Place these UTF-8 text files next to the launcher executable:

- `launcher_content/news.txt`
- `launcher_content/patches.txt`

Include them as ordinary files in the existing update package. They are read on launcher startup and reloaded after a successful update. This gives the launcher content that can change without rebuilding the executable, through the existing patch distribution rather than a new web service. There is no separately polling online news API in this change.

Both files use the same format. Each entry has a title, date/display label, summary, then body text. A line containing exactly `---` separates entries. Put newest entries first. Headings start with `## `; bullets start with `- `. Empty lines separate paragraphs. Other text is plain text, not HTML or a full Markdown implementation. No remote links, script execution or images are loaded from these files.

```text
Update title
2026-10-05
A short description of this release.
## Highlights
- Describe a change that was actually released.
- Describe another change.

## Improvements
A longer paragraph can wrap and scroll in the reader.
---
Previous update title
2026-09-28
A short description of the earlier release.
## Changes
- Describe the earlier release here.
```

Files are limited to 256 KiB each and 32 entries. Missing, empty, oversized or unusable files retain the embedded fallback for that category. Titles, date labels and summaries are bounded. The fallback contains launcher information and explicitly states that game release notes have not yet been published; it does not invent game patches or features.

The Home page uses the first two news entries and the first patch entry. News lists three articles per page. Patch history lists five releases at a time. Long article bodies scroll independently of the update dock.

## Settings and updater behavior

- **Open game folder** opens the installation directory.
- **Check and repair files** reruns the updater's existing verification and replaces missing/changed files. It is available after the previous run has ended, including after a failed update; concurrent repair requests are rejected. Play is disabled while the new run checks files.
- **Keep launcher open** is persisted to `launcher.ini` in the installation directory after Save changes. Cancel restores the saved value. A write error is reported.
- **Open launcher logs** opens the existing Documents/MMORPG/Logs directory.

Updates and game launch now resolve relative to the launcher executable's directory, even if it is started from a different working directory.

Download pause, bandwidth limits, launch-at-login registration and installation relocation from the concept images are not exposed as nonfunctional controls. Actual network transfer-rate/ETA reporting is also not added: the current progress callbacks measure processed, uncompressed file data rather than network bytes. The existing honest file/byte totals remain in the update dock.

The native macOS Cocoa launcher is unchanged; the redesign uses the portable rendering core through the Windows host.

## Controls

Click a navigation tab or news card to open it. Use the mouse wheel or Up/Down, Page Up/Page Down and Home/End to scroll articles. Tab and Shift+Tab move focus; Enter or Space activates the focused control. Focused controls receive a gold underline. Enabled controls use a hand cursor. The window remains draggable from chrome outside the controls.

## Validation

`launcher_tests` covers article parsing, CRLF/UTF-8 content, invalid/oversized input, bounds, file overrides and offline fallback, update model transitions, and Windows updater restart/recovery. The existing `updater_tests` remains the regression suite for manifest handling, network timeout/cancellation and retries.

```powershell
cmake --build build --config Debug --target launcher launcher_tests updater_tests
ctest --test-dir build -C Debug -R '^(launcher_tests|updater_tests)$' --output-on-failure
```
