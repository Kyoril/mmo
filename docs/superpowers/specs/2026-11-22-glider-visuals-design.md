# Glider visuals — design (prototype)

Status: draft v2 (back-mounted, with sounds), waiting for approval. Builds on the traversal test field
(`2026-11-21-traversal-pillar-design.md`, merged as 0959b8ea).

## Intent

Gliding works but is invisible: the character falls slowly in its falling pose.
The glider should be seen in-game, with its own character animation and a few
particle effects, so the mechanic reads as part of Alestia and not as a hack.
Prototype quality: everything is generated by us (no bought asset pack exists),
art can be replaced later without code changes.

## Look (decided by the user)

- Mechanical / technical glider **worn on the back**, not held above the head.
- Da Vinci flying machine style: wooden struts, stretched linen, ropes, leather straps.

## Goals

1. **Glider model** — a wing frame strapped to the back: a wooden spine along
   the back, two wings of wooden ribs with stretched linen (about 3 m span),
   ropes from the wing tips to hand grips, leather harness straps. Modelled by
   script in Blender (scratchpad), own wood and linen textures, imported with
   `mmo_edit --import-fbx` like weapons. Attached to the upper-body bone
   (spine_03 / Back_M socket), so it moves with the torso.
2. **"Glide" animation** — body tilted forward towards horizontal, arms spread
   holding the grips at the wing ribs, legs trailing slightly behind, calm sway
   loop. Posed in Blender on the real character mesh and skeleton,
   checked on renders together with the glider, then written directly into the
   four player skeletons (HumanMale, HumanFemale_V2, OrcMale, OrcFemale; undead
   share the human ones). FBX animation import is avoided because of the known
   pivot double-apply trap.
3. **Particles** (alpha only — the engine has no additive blending or bloom):
   - wind threads trailing from both wing tips while gliding,
   - a short dust / cloth burst when the glider opens,
   - visible updraft columns above area triggers with `updraft_strength > 0`.
4. **Sounds** (generated with the ElevenLabs MCP through the existing sfx
   pipeline, as SoundEntry data):
   - open: wood creak + linen snapping taut,
   - close: wings folding, short wood clack,
   - wind loop while gliding (positioned on the unit, so others hear it too),
   - updraft: a rising whoosh when entering an updraft.
5. **Client behaviour**
   - new animation slot `GLIDE` (both proto copies), falls back to `Falling`
     when a model has no Glide clip,
   - while the unit has the `Gliding` movement flag the glider is attached;
     it unfolds / folds in about 0.25 s on open / close,
   - other players see it too: the flag already replicates with every movement
     packet. **No protocol change.**

## Non-goals

- Glider skins / collectible variants.
- Release polish; the test field stays GM-only (spells 1436/1437).

## Constraints

- Feature branch `feature/glider-visuals`, fast gate before /ship.
- One-off Blender / Python scripts live in the scratchpad, only the resulting
  assets and C++ are committed.
- Client threading rules: attach / detach on the main thread only.

## Approaches considered

- **Animation via FBX import** (`--import-fbx-animations`): proven path, but the
  player rigs carry Assimp pivot bones that were applied twice before; rejected
  in favour of writing the clip straight into the `.skel`.
- **Pose written blind in Python** (bone offsets without a preview): cheapest,
  but no way to check the hands meet the grips; rejected.
- **Chosen:** pose in Blender on the real mesh, verify on renders, write the
  clip into the `.skel` files.

## Left to the builder

Exact bone offsets, glider dimensions (roughly 3 m span), particle tuning,
fold animation curve, verification captures in the test field (map 2).
